# Blender 产品建模与广告摄影

交付可编辑、可追溯的 Blender 主资产、链接场景与实际渲染图。围绕用户指定的产品和参考画面工作；尺寸、结构、品牌图案优先于自由美化。不要把 AI 生成图当成已经完成的 Blender 模型或渲染。

## 先判断当前任务

| 请求 | 从哪里继续 | 需要读取的指南 |
| --- | --- | --- |
| 用实拍、尺寸、贴图建新产品 | 资料与尺寸表、结构草模 | [资料与建模](references/intake-and-modeling.md) |
| 更新全项目的瓶盖、包装、材质 | 确认主资产及依赖场景 | [资产与版本](references/assets-and-versions.md)，并按需读建模指南 |
| 新建场景、对齐参考、给几种机位或灯光 | 已确认的主资产与场景约束 | [摄影与材质](references/camera-and-lighting.md)、资产与版本 |
| 只改一个场景的光线、位置或湿润效果 | 用户指定的那个场景版本 | 摄影与材质、资产与版本 |
| 渲染 6000px、透明底、白底 | 已确认的场景快照 | [渲染与交付](references/render-and-deliver.md) |
| 整理旧项目、恢复旧版本 | 现有文件、预览、版本记录 | 资产与版本 |
| 塑料/金属等质感不对，建立材质样板 | 部件的表面工艺、尺度与中性对照 | [材质与工艺](references/materials-and-finishes.md)，摄影与材质 |
| 如何补拍、用照片扫描或高斯泼溅 | 输出是否需要编辑/换光，素材覆盖 | [实拍与重建选择](references/capture-and-reconstruction.md) |
| 广告主视觉、精修分层、系列投放 | 拍摄目的、品牌限制与交付用途 | [广告与后期](references/advertising-and-compositing.md)，摄影与材质、渲染与交付 |

只执行本次任务涉及的阶段。明确参考图时先匹配它；只有用户要挑选方向或没有摄影方向时，才制作有区别的机位/灯光小样。无需为每个阶段机械地追加确认。

## 接手时的动作

1. 读取用户指定文件、项目说明和现有资产/场景清单；实际查看参考照片、贴图和最近确认的预览。若用户手动改了 `.blend`，以该文件内的当前相机和对象状态为起点。
2. 确认本次输入场景、产品版本、需改变的内容与输出路径。遇到“原来那个”，用版本记录和对应预览定位；若确实不能唯一定位，再针对版本询问。
3. 发现可用的 Blender MCP 或本地 Blender 程序。MCP 适合查看与调整当前 GUI 场景；可用 CLI/Python 时，后台生成和渲染可以直接进行。不虚构 MCP 已连接，不猜测服务端口。
4. 保护 GUI 中尚未保存的用户修改；不要为了运行脚本直接用旧文件替换当前会话。修改前另存工作版本，正式渲染用已保存的确切输入。
5. 检查实际 Blender 版本和可用 API。工具路径随环境发现，不把某台电脑的用户名、GPU 类型或产品尺寸写成通用要求。

## 工作流程

### 1. 资料与可信尺寸

把实拍、尺寸、贴图、场景参考分开理解。确认正反左右、含盖高度、宽深方向、包装开法、每盒数量和材质分区。必要时用 [产品资料模板](assets/product-brief.md) 整理；模板不用全填，但影响本次建模的必需信息要先确认。

新产品先清点六类依据：实测尺寸或用户许可的暂定尺度、各部件基材/工艺或视觉近似许可、分件与开合、关键视角覆盖、贴图面对应、本次交付目标。可以先看资料和列出可确定的事实；若仍缺必需项，将问题合并向用户问清并等待答复，之后再建模或渲染。不得为了先出草模而自定真实尺寸、材料或隐藏结构。

照片比例受透视影响；展开图可能含出血、折边和粘口。用可信实测尺寸锚定其余比例，给推估值标记依据与可信度。用户明确允许推估时记录该授权与取值依据；没有授权时暂停依赖该信息的制作。

涉及新材质时区分“基材”和“可见表面工艺”；照片不能唯一确定材质参数。需要补拍或重建时按实拍与重建指南选择路线，不把高斯泼溅当成必需依赖。

### 2. 结构与贴图

先做真实比例的轮廓、分件和开合，再做材质细节。新模型通常提供正面、侧面和能说明结构的低成本预览；近景再检查瓶口、盖、盒边、铰链与内托。

对包装先建立“刀模区域 → 实体面”的对应，确认 UV 后再做摄影。保留用户的字、Logo、图案和原始文件；不要因场景构图改变印刷内容。SVG 用于高质量贴图来源，不默认把整张包装图转成海量曲线几何。

新建或大幅改材质时，先在固定中性测试光下对照实拍，再进入广告氛围光。区分材质球演示、产品形状上的验证和实物校准；预设能正确运行不代表已精确匹配实物。镜面/拉丝金属、半透明塑料、涂层等读取材质与工艺指南。

### 3. 发布可复用主资产

将产品几何、UV、基础材质、贴图和结构控制放入主资产；把灯光、相机、布景和摆放放入场景。多个场景通过稳定集合名链接同一资产。主资产更新需要场景重新载入；已渲染 PNG 不会自动更新。

分清产品本身修正与某张照片的表现调整。场景专用深色玻璃、凝露、液流等要标成有来源的变体，不悄悄推广到全部场景。详见资产与版本指南中的同步边界。

### 4. 摄影方案与选择

先锁定产品相对位置、前后距离和相机，再比较灯光。无指定参考且用户希望挑选时，可给正面平视、轻微三分之四、低机位英雄镜头等 2–4 张小样；在选定或最接近目标的机位上给 2–3 个灯光方案。

广告场景先明确主体卖点、必须看清的标识、留白与允许的艺术化范围。按表面反射选择柔光幕、灯、白卡和黑卡，而不是所有产品套同一套光；亮面产品的高光形状也是构图的一部分。

用带编号、同尺寸的联系表或单张预览便于选择。记录每张对应的相机、镜头、光组和场景文件。用户已指定参考或某个参数时，直接沿用该选择，不强迫重选。

### 5. 局部迭代

先区分问题的来源：透视、摆位、模型结构、材质、光比、曝光或颜色管理。一次围绕用户指出的问题修改，使预览能说明改变。产品落地、文字方向、透明玻璃边缘、盒盖开合和接触阴影都要在实际画面中检查。

“更平”“更暗”“玻璃更棕”“水珠更大”不是同一个参数。按摄影与材质指南处理，不用全局曝光替代所有修正。

### 6. 正式输出

按本次授权的尺寸与格式渲染；未指定高清时，模型/场景调整通常先出长边约 1000–1600px 的预览。用户已明确要求高清且场景明确，直接完成，不再重复索要确认。

锁定场景快照、依赖版本、相机、帧、颜色管理和灯光。输出后检查真实像素、完整画幅、透明通道以及可打开的文件，再交付。不要把低清放大称为原生高清渲染。

## 随附资源

- [产品资料模板](assets/product-brief.md)：整理输入、推估项和拍摄用途。
- [项目索引模板](assets/project-index.json)：新项目可复制后填入；已有清单时沿用原格式，不另造互相矛盾的清单。
- [scene_report.py](scripts/scene_report.py)：在 Blender 中读取相机、灯光、依赖、渲染配置及评估后实例包围盒；不保存或改写 `.blend`。
- [render_still.py](scripts/render_still.py)：Cycles 单张 PNG 渲染，支持长边/短边/指定尺寸、GPU 检测和真实输出尺寸记录；不保存场景，默认拒绝覆盖已有输出。
- [材质起点](assets/material-presets.json) 与 [build_material_lab.py](scripts/build_material_lab.py)：生成独立材质样板棚，含可编辑节点、三种反射灯组起点；也可按指南导入函数创建新材质/光组，不覆盖产品材质。

`render_still.py` 还支持明确请求的原始多层 EXR、材质/对象遮罩和分灯组输出；它不等同于自动精修，也不保留成片合成效果到原始 EXR。用法、边界和验证项目见渲染与交付指南。

脚本的调用方式和限制见渲染与交付指南。它们不替代建模判断、目测比对、精确接触或穿模检查。

## 最终交付说明

用用户能理解的语言交代本次改动、预览或成片、可编辑文件和仍属推估的关键点。给可点击的绝对路径。只有执行并完成的动作才用“已建好/已渲染/已同步”；文件存在但未切换到该状态时，不说“已恢复”。
