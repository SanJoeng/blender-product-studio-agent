# 渲染、诊断与交付

## 渲染前

确认输入是用户刚接受的场景，记录相机、帧、主资产/变体版本和预览。场景包含用户手改时先保存对应快照。正式渲染期间不要发布同一主资产的新版本；必须并行改产品时使用独立候选文件或冻结依赖快照。

核对输出含义：

- “长边 6000px”按既定比例缩放，例如 3:4 得到 4500×6000。
- “短边 4000px”按短边计算；“4000×4000”是明确宽高，改变比例后需要检查构图。
- 只说“6000px”且已有竖横构图时，通常按长边处理并在更新中说明。
- 检查 resolution_percentage、像素长宽比、渲染边界、裁切和合成器缩放，防止实际输出不同。

先查贴图/库/模拟缓存、相机、可见性、接触、穿模、裁切、alpha、颜色管理。文字锐度不足先查原图有效像素与 UV，增加采样不能恢复丢失的文字细节。

## 工具和设备

后台 CLI 适合独立渲染；启动前了解历史脚本是否包含清场、重新建模、覆盖主资产或自动渲染。MCP 的 GUI 连接与后台 `blender -b` 是两条通路；插件提示后台无法启动 MCP 不等于渲染失败，以实际退出码、渲染日志和输出为准。

Cycles 优先尝试当前可用的 GPU，检测实际后端和启用的设备，不只写 `scene.cycles.device='GPU'` 就宣称 GPU 正在工作。一次内存不足不能推导为这台机器永久无法 GPU 渲染。

高分辨率前先看正在运行的渲染与内存压力。通常单个重渲染顺序执行；不要仅为并行而让多个大图争抢统一内存。用户要求比较 CPU/GPU 时使用独立输出路径，说明耗时和资源竞争对比较的影响。

GPU 内存失败时：记录原始错误与任务设置；退出失败进程释放资源；检查其他任务、贴图和不必要的细分/实例实现；如当前 Blender 支持，使用合适的分块渲染设置。保持画面不变的前提下可重试一次。降低采样不保证解决显存峰值，不偷偷缩小输出或降低重要几何/贴图质量。

若仍失败，说明情况后在新进程回退 CPU；用户明确要求再试 GPU 且条件变化时可以继续尝试。不要让失败重试无限循环，也不要因可恢复的计算错误要求用户重复授权原本的渲染任务。

## 随附脚本

以下命令中的 `blender` 表示已发现的 Blender 可执行文件；`SKILL_DIR` 表示这个技能目录，`SCENE` 与 `OUT` 使用实际绝对路径，shell 中正确引用空格和中文。示例参数不是固定的产品要求。

读取场景报告，不渲染、不保存源文件：

```bash
blender --background "$SCENE" --python-exit-code 1 --python "$SKILL_DIR/scripts/scene_report.py" -- --output "$OUT/scene-report.json"
```

Cycles 预览：

```bash
blender --background "$SCENE" --python-exit-code 1 --python "$SKILL_DIR/scripts/render_still.py" -- --output "$OUT/shot03_v006_preview.png" --stage preview --long-edge 1280 --device auto
```

用户明确要求的正式图：

```bash
blender --background "$SCENE" --python-exit-code 1 --python "$SKILL_DIR/scripts/render_still.py" -- --output "$OUT/shot03_v006_6000.png" --stage final --long-edge 6000 --device auto
```

支持 `--short-edge 4000` 或 `--size 4000 4000`；三种尺寸参数互斥。可选 `--camera 名称`、`--frame 帧号`、`--samples 数量`、`--device gpu/cpu`、`--transparent` 或 `--opaque`。PNG 支持 `--depth 8/16`，EXR 支持 `--depth 16/32`，默认 16。透明参数仅控制 film/输出，背景物体和合成器仍由场景负责。

脚本适用于 Cycles 单张 PNG 或原始多层 EXR。预览默认限制到长边 1280 与最多 32 samples；final 默认保留输入场景的采样与降噪，不擅自降低质量。它不保存 `.blend`，所以最终设置记录在同名 `.render.json`；需要保存输出设置时另存渲染场景。

为避免意外副作用，脚本会拒绝缺失源文件、已有输出/记录/锁文件、活动的合成器 File Output 节点、局部渲染边界和多视图输出。对多文件合成器输出、特殊裁切或节点树流程另写有明确路径的脚本，不绕过保护后盲跑。

脚本打印输入、分辨率、采样、检测到的设备与开始/结束信息，并写 `preparing/rendering/completed/failed` 状态。它不提供可靠采样百分比；Blender 原始日志才是进一步进度来源。渲染被外部终止时可能留下 `.lock`，先核对其中 PID 和对应命令确已结束再移除该任务的锁。

## 可选广告精修 EXR

只有需要精修/分灯组时使用；更多通道会增加内存与磁盘。输出后缀 `.exr` 明确选择原始场景线性多层输出，不是经过合成器和显示变换的成片：

```bash
blender --background "$SCENE" --python-exit-code 1 --python "$SKILL_DIR/scripts/render_still.py" -- --output "$OUT/shot03_v006_layers.exr" --stage final --long-edge 6000 --studio-passes --light-groups --device auto
```

`--studio-passes` 为启用的视图层增加 Combined、深度、法线、漫反射/反射/透射、发光/环境及对象/材质 Cryptomatte。`--light-groups` 需与它同时使用：保留已有灯的分组，给未分组的本地灯和本地 World 建组；不能赋组的链接灯/World 报错，不静默忽略。发光网格不会自动分组，需要另行明确设计；各组相加前检查贡献完整性，保留 Combined 为基准。

EXR 路径会在当前后台进程禁用合成器和序列编辑器，保存原始视图层；不修改源 `.blend`。活动 File Output 节点仍被拒绝，不能借此绕过未审查的写出路径。原有合成器调色、背景合成和锐化不写入原始多层 EXR，应另交付成片 PNG。脚本不会创建独立阴影层、PSD 或自动精修方案。

在支持 `media_type` 的版本中先选择多层图像类型；支持时明确使用兼容性较好的 interleaved 单部件 EXR 与无损 ZIP。不要把新版本默认 multipart 文件交给只理解旧格式的下游；需要 multipart 时另做读取与通道验证。脚本只保证已测试版本的行为，其他版本先跑小图检查。

记录包含实际 EXR 尺寸、通道名称、Cryptomatte 元数据与灯组映射。头部验证不代表像素完好或分层效果正确：正式交付应在 Blender/支持 EXR 的软件解码并查看 Combined，抽查遮罩/灯组；背景、Alpha、玻璃折射与阴影要按实际用途验收。透明产品也不保证贴到任意新底图上都物理正确。

## 过程与故障说明

长任务用有界等待查看已启动进程和日志；有具体变化才解释原因、剩余动作或新的预计耗时。CPU 很忙只能说明进程活跃，不能据此声称“快好了”或某个采样百分比。进程结束不等于成图成功，需检查退出码和实际文件。

只报告可证实的性能结论：同尺寸/采样/场景的 GPU 可能比 CPU 快，但不同任务、并发负载或首次编译会影响用时。保留实际设备名和耗时，不把单次表现写成普遍保证。

## 出图后的最低核对

1. 文件存在且可解码，真实宽高符合约定；透明图有有效 alpha。
2. 缩略预览看全图，必要处看实际像素的文字、水珠和边缘；没有因正式设置产生新的缺失、裁切或贴图变化。
3. 透明图在浅/深背景上查看；需要纯白的资料图检查背景数值和阴影要求。
4. 记录源场景、依赖、设置和输出对应，更新项目当前工作/接受版本与已重渲列表。
5. 交付预览/原图链接、像素尺寸和对应可编辑场景。没有重渲染的旧图明确保留旧状态，不用新场景文件名暗示它已更新。
